# Redis 专项测试案例

基于《公共技术服务接入操作程序》推荐的专项测试案例。

## 1. 网络抖动演练

**测试目标**：模拟应用网络抖动场景，验证应用层重试机制。

**测试步骤**：
1. 配置应用到 Redis 间的数据包丢包（可配置丢包率及丢包时间）
2. 观察应用是否具备重试写入机制
3. 验证数据最终一致性

**通过标准**：应用在网络抖动恢复后，数据写入最终成功。

## 2. 全量宕机演练

**测试目标**：模拟 Redis 服务全部宕机，验证应用自动重连能力。

**测试步骤**：
1. 模拟 Redis 服务（主从模式/集群模式）全部宕机
2. 观察应用故障处置行为
3. 恢复 Redis 服务后，验证应用自动重连

**通过标准**：Redis 服务恢复后，应用能够自动重连并恢复正常服务。

## 3. 主从切换演练（主从模式）

**测试目标**：模拟 Redis 主从切换，验证应用自动重连。

**测试步骤**：
1. 模拟 Redis 主节点故障
2. 观察哨兵选举和主从切换过程
3. 验证应用是否自动重连到新主节点

**通过标准**：主从切换完成后，应用自动重连至新主节点。

## 4. 分片故障演练（集群模式）

**测试目标**：模拟集群分片全部故障，验证应用自动重连。

**测试步骤**：
1. 模拟某个分片的主从节点全部故障
2. 观察 Redis 集群状态变化
3. 验证应用自动重连能力

**通过标准**：故障分片恢复或重建后，应用恢复正常访问。

## 5. 分片主从切换演练（集群模式）

**测试目标**：模拟集群分片主从切换，验证应用自动重连。

**测试步骤**：
1. 模拟某个分片的主节点故障
2. 观察分片主从切换过程
3. 验证客户端是否自动识别新主节点并重新连接

**通过标准**：分片主从切换完成后，应用自动重连至新主节点。

## 6. 容灾切换演练（容灾模式）

**测试目标**：模拟同城双活架构下 Redis 全部宕机，验证自动切换。

**测试步骤**：
1. 模拟一地 Redis 服务全部宕机
2. 观察 Proxy/DNS 容灾切换过程
3. 验证应用是否自动切换至另一地 Redis 服务

**通过标准**：容灾切换完成后，应用自动切换至容灾机房 Redis 服务。
