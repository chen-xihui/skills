# Redis 容灾故障排查

## 容灾场景概述

基于《公共技术服务接入操作程序》，Redis 缓存服务提供跨机房的数据同步以及路由网关能力，用于支撑双多活或单元化建设。

## 容灾功能限制排查

| 限制项 | 说明 | 排查要点 |
|--------|------|---------|
| 网络分区 | Proxy 自动容灾切换不能处理网络分区 | 出现网络分区时，主机房、容灾机房降级为两套独立缓存 |
| 数据一致性 | 读写分离存在毫秒级同步时延 | 写入后可能读取不到，需通过重试机制规避 |
| 接口限制 | 使用 Proxy 组件时，不支持事务和 keys 命令 | 检查是否使用了 multi、exec、discard、keys 命令 |

## 容灾切换排查流程

### 主动切换异常排查

1. 检查缓存服务控制器健康检查配置
2. 确认健康检查周期和触发容灾切换的缓存分片数量
3. 检查主机房缓存服务健康状态检测日志
4. 验证流量是否已切换至灾备机房

### 手动切换异常排查

1. 确认 Proxy 标准化缓存服务流量切换是否完成
2. 检查 DNS 域名解析是否正确指向容灾机房
3. 验证客户端是否成功重连

## Proxy 兼容性检查

使用 Proxy 组件时，需确保：
- 客户端按主从模式配置
- 配置重连相关配置，确保容灾切换后自动重连
- 使用 scan 命令替代 keys 命令
- 不使用 multi、exec、discard 等事务命令

## 数据同步时延排查

### 读写分离场景

- 写请求路由至逻辑主机房，读请求路由至就近机房
- 仅支持最终一致性，数据存在同步时延
- 推荐在读取接口中增加重试逻辑

### 排查步骤

1. 确认数据同步方向（单向/双向）
2. 检查同步时延是否在可接受范围内
3. 验证读取重试逻辑是否生效
