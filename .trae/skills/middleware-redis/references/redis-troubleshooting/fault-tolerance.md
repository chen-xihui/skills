# Redis 容错开发检查清单

在故障排查时，也应检查应用侧是否按规范实现了容错机制。

## 健康检查

- [ ] 是否设计了缓存检查接口（Ping、Set/Get 定时检查）
- [ ] 是否将缓存检查加入应用健康检查接口
- [ ] 是否新增应用客户端访问缓存健康指标
- [ ] 是否配置了应用告警

## 异常处置

| 措施 | 检查要点 |
|------|---------|
| 服务熔断 | 是否合理配置超时时间，访问异常时是否熔断缓存请求 |
| 服务降级 | 是否设计服务降级，访问异常时是否降级访问数据库 |
| 错误处理 | 是否合理捕获异常，是否根据错误类型打印关键日志 |
| 请求重试 | 是否针对网络抖动等场景设计重试逻辑，重试接口是否满足幂等性 |

## 核心接口可靠性

核心交易接口应保证：
- 极端情况下（网络异常、物理设备异常）保持持续可用
- 缓存服务主从切换、全量宕机时，核心交易接口应保持可用
- 通过熔断 + 降级 + 重试机制保障业务连续性
