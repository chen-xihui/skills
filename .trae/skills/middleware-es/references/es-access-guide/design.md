# 设计指引

## 3.1 Elasticsearch 依赖设计

> ES 组件可提升数据查询效率，推荐用于交易系统之外需要高效搜索和实时数据分析的场景。关键交易接口不应强依赖 ES 服务。

**交易类接口**：设计交易接口时不应强依赖 ES 服务，当访问索引数据失效或不可用时，应降级处理请求，确保交易不受影响。

**非交易类接口**：应充分评估接口影响范围，避免搜索接口异常造成主体业务不可用，同时应考虑接口熔断设计。

## 3.2 数据隔离规则

接入系统应在本系统范围内使用 ES 服务，不宜多个系统混用。推荐按以下维度拆分：

- **按数据业务领域**拆分索引数据，存储至多套 ES 服务；同一领域各微服务可使用一套 ES
- **按业务可用性等级**拆分：关键核心业务推荐使用独立 ES 服务强隔离数据；默认场景下采用索引进行业务逻辑隔离

## 3.3 部署区域原则

- 接入系统与 ES 服务推荐部署至相同网络安全域，避免跨网络域访问
- ES 服务访问地址不能发布至公网

## 3.4 命名设计

**索引命名规范**
- 以字母开头，长度 1~63 字符
- 由小写字母、数字和下划线组成
- 应清晰表达业务含义，多语言场景增加语言标识后缀
- 示例：`user_feature`

**映射字段命名规范**
- 以字母开头，长度 1~63 字符
- 由小写字母、数字和下划线组成
- 应清晰表达业务含义，多语言场景增加语言标识后缀
- 示例：`user_name_zh`

## 3.5 分词器选择

| 分词器 | 说明 | 参考使用场景 |
|--------|------|------------|
| standard | ES 默认分词器，按空格 + 标点拆分 | 英文或混合文本，非精细中文 |
| keyword | 不分词，整体索引 | 精确匹配字段，如 ID、手机号、订单号 |
| whitespace | 按空格拆分 | 英文多词短语场景，保留标点 |
| simple | 去掉标点的小写分词 | 简单英文文本 |
| language-specific | english、french、porter_stem 等 | 语言分析、词干提取 |
| ik_max_word/ik_smart | 中文分词插件 | ik_max_word 细粒度，ik_smart 粗粒度；中文搜索全文检索 |
| pinyin | 将汉字转换为拼音索引 | 中文拼音搜索，适合姓名、城市等模糊匹配 |
| 自定义 analyzer | 可组合 tokenizer + char_filter + filter | 支持同义词、拼写纠正、停用词处理 |

## 3.6 索引设计

- **主分片数量**：创建索引时必须指定，且创建后无法修改；推荐主分片数为数据节点的 3 倍，确保单个索引分片存储不超过 50GB
- **分片副本数**：创建时必须指定，最小设置为 1；普通系统推荐副本数为 1，重要系统推荐副本数为 2
- **分片数量限制**：单个节点最大分片限制默认为 1000，超过则无法创建新索引
- 推荐使用索引模板规范索引配置

## 3.7 Mapping 设计

**字段类型选择**

| 字段 | 适用场景 | 优势 |
|------|---------|------|
| keyword | 精确匹配、聚合、排序 | 高性能精确查询 |
| text | 全文搜索、模糊匹配 | 支持分词与语义分析 |
| integer、long | 范围查询、统计聚合 | 高效数值计算 |
| date | 时间范围过滤、时序分析 | 支持日期表达式 |
| object | 嵌套对象 | 表达复合数据类型 |
| nested | 独立索引的嵌套对象 | 可用于数组对象查询 |
| boolean | 布尔类型 | 适用于开关状态等 |

**设计原则**
- 字段应显式定义，不推荐使用动态 mapping
- 预留字段支持未来业务扩展
- 中文字段、多语言推荐使用多字段配置（multi-fields）
- 没有检索需求的字段应设置 `index` 为 false
- 控制字段长度，避免大文本字段占用过多内存
- 没有聚合需求的字段建议 `doc_values` 设为 false

## 3.8 查询设计

**查询方式对比**

| 查询方式 | 用途 | 特点 |
|---------|------|------|
| term | 精确匹配单个词条 | 不分词，适用于精确查询 |
| terms | 精确匹配多个词条 | 一次查询匹配多个值 |
| match | 全文检索，分词处理 | 支持模糊匹配和相关性评分 |
| multi_match | 多字段全文检索 | 在多个字段上进行全文检索 |
| bool | 组合多个查询条件 | 灵活性高，适用于复杂查询场景 |
| match_phrase | 短语匹配 | 支持设置 slop，允许位置偏移 |
| range | 范围查询 | 支持 gte、lte 等条件 |
| exists | 检查字段是否存在 | 匹配包含指定字段的文档 |
| fuzzy | 模糊匹配 | 允许一定编辑距离 |
| wildcard | 通配符查询 | 支持 * 和 ? |
| script | 脚本条件匹配 | 支持自定义匹配逻辑 |

**功能选择原则**
- 查询选择 DSL 语法，不直接拼接字符串，避免注入
- 多字段查询使用 multi_match，单字段查询使用 match
- 精确匹配使用 term/terms，模糊/全文匹配使用 multi_match/match
- 复杂查询必须用 bool，保持 must、should、must_not、filter 语义清晰
- 排序字段必须使用 keyword、numeric、date，禁止使用 text

**性能优化原则**
- 推荐使用 filter 代替 query（filter 可缓存，效率更高）
- 避免高开销查询，减少 wildcard、regexp 使用
- 控制查询分页大小，避免深分页；推荐使用 search_after 或 scroll
- 控制结果返回字段，避免使用全量 _source

**聚合查询设计原则**
- 聚合字段必须使用 keyword/numeric/date，不能对 text 聚合
- 复杂多层聚合必须设置合理 size 大小
- 避免对高基数、大数量字段做 terms 聚合
- shard_size 可基于分片数量计算：`shard_size = 期望结果数 × 索引主分片数`

**查询相关性设计**
- 推荐使用字段权重 `^n` 或 boost 设置权重（如 `title^3`、`content^1`）
- 推荐使用 function_score 结合时间、权重调整评分
- 推荐使用 _explain API 优化搜索打分
- 推荐使用 _profile 优化查询执行
