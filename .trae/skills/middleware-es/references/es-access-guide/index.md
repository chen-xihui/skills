## 一、基本概念

### 1.1 部署模式

| 模式 | 说明 |
|------|------|
| 混合模式 | 同一个 ES 节点承担多种功能角色（master、data 等），节点数相对较少，节省资源，但调度和计算共用资源，无法进一步拆分不同的存储节点 |
| 角色分离模式 | 不同的 ES 节点承担不同功能角色，分为 master 节点、data 节点等，后续集群扩展更加灵活，可单独扩展某些类型的节点数量 |

### 1.2 常用节点角色

| 角色名称 | 说明 |
|---------|------|
| master 节点 | 集群层面的管理，创建和删除索引、跟踪节点、决定分片分配等；因选主需要，节点数为奇数且至少 3 个 |
| data 节点 | 数据落地存储、数据增删改查、缓存、聚合等操作的执行；节点数超 5 个时需在性能环境验证通过 |
| data_hot 节点 | 保存最近、最常访问的数据，仅角色分离模式支持 |
| data_cold 节点 | 保存不经常访问且通常不更新的数据，仅角色分离模式支持 |
| client 节点 | 不会成为主节点，也不存储数据，只负责处理用户请求和负载均衡，仅角色分离模式支持 |

### 1.3 持久化模式

ES 默认开启持久化能力，所有数据均存储于本地存储盘，但数据落盘过程非强一致，无法确保 RPO=0。

**数据写入流程**：
1. 索引数据写入内存缓冲区，占满或固定时间间隔（默认 1s）执行 refresh 操作，将数据生成 index segment 文件并写入 Translog 日志文件系统缓存区，此时可提供 search 查询
2. 内存缓冲区写入文件系统缓冲区后清空，继续写入新数据
3. Translog 日志文件达到阈值或固定时间间隔（默认 30s）触发 flush 操作，index segment 文件被 fsync 强制写入磁盘，并清理 Translog

| Translog 刷盘模式 | 说明 |
|---|---|
| 同步刷盘模式（默认） | 每次写入、更新、删除操作后立刻执行 fsync 落盘，数据可靠性更强，性能较低 |
| 异步刷盘模式 | 根据同步间隔（默认 5s）周期性刷盘，性能更佳，但数据可靠性相对低 |

### 1.4 核心术语

| 术语 | 说明 |
|------|------|
| 集群（cluster） | ES 的最小服务实体，包含多个节点，主节点负责管理集群范围内的所有变更 |
| 节点（node） | 集群中的一个应用实例节点，运行态为 Java 进程，可通过增减节点实现扩缩容 |
| 索引（index） | 文档的集合，数据存储在单个或多个 Index 中，单个索引有一个或多个分片 |
| 分片（shards） | 数据存储的容器，单个完整索引可分成多个分片，分布到不同节点 |
| 主分片（primary shards） | 索引存在主分片，在创建索引时确定主分片数，创建后无法修改 |
| 副本分片（replica shards） | 每个索引支持多个副本分片，提高容错性和查询效率 |
| 文档（doc） | 索引内的数据内容，支持数据检索、排序和过滤 |
| 字段（field） | 文档的子集数据，常见类型包括 keyword、text、数字、对象等 |
| 词项（term） | 全文本内容在分词后得到的词语 |
| 聚合查询（aggregations） | 用于对数据进行统计、分析和分组 |

## 二、服务特点与模式

### 2.1 服务特点

- **多部署模式支持**：支持混合部署和角色分离部署
- **信创适配**：支持鲲鹏、海光芯片、麒麟操作系统
- **局部故障自愈**：服务器宕机等异常场景时自动恢复、重启
- **高可用性**：索引多分片及副本分片备份，部分节点异常时可提升副本分片为主分片继续服务

### 2.2 服务模式选型

**混合部署模式**
- 集群内各节点角色相同，任何节点均可成为 master 节点，每个节点也都存储数据
- 一般设置 3 个及以上奇数个节点
- 扩展灵活性相对较差，推荐用于小规模、无扩展需求的应用

**角色分离部署模式**
- 集群内提供多种角色的节点，包括 master 节点（3 个）、data 节点（根据业务数据量确定）以及 client 节点
- 扩展灵活性高，可扩展特定类型节点数量
- 推荐用于需要大规模数据存储或高并发请求访问的场景

### 2.3 服务规格选型

| 版本 | 部署模式 | 节点资源 | 分片 | 复杂查询 TPS | 简单查询 TPS |
|------|---------|---------|------|------------|------------|
| 低配 | 混合 | 2C/4G/100G | 3 | ≤500 | ≤2000 |
| 中配 | 分离 | 4C/8G/200G | 3 | ≤1000 | ≤4000 |
| 高配 | 分离 | 8C/16G/500G | 3 | ≤2000 | ≤8000 |
| 超高配 | 分离 | 16C/32G/1000G | N（根据数据量） | ≤1000×N | ≤4000×N |

**磁盘容量规划**：
- 日增量 = 文档数 × 单文档平均大小 × 副本数 / 压缩比（默认 LZ4）
- 申请存储量 = 存储天数 × 日增量 / 70%（预留 30% 存储）
- 单个节点存储上限为 1000G

### 2.4 持久化选型建议

| 方案 | 适用场景 | 配置示例 |
|------|---------|---------|
| 同步刷盘（默认） | 订单、交易类等实时业务场景 | `refresh_interval: 1s`, `translog.durability: request` |
| 异步刷盘 | 埋点类非实时业务场景 | `refresh_interval: 30s`, `translog.durability: async` |
